    テスト設計書（TDD）

    概要

    本書は implement-spec のテスト先行フェーズで使用する TDD テスト設計書。 テストフレームワークは Vitest（確定は実装時）。 外部依存（fe-siken.com / AnkiConnect / Obsidian requestUrl / Vault API）はすべてモック化・スタブ化する。

    fixture HTML

    HTML 抽出テストには実ページ構造に基づく fixture を用意する。 fixture は以下の要素を再現すること:

    • <meta property="og:title" content="...">
    • <div id="mondai">
    • <ul class="selectList"> 内の <li> 要素
    • 各 <span id="select_a|select_i|select_u|select_e">
    • <button class="selectBtn" id="t"> （正解のみ id="t" を持つ）
    • <h3>分類 :</h3> の直後の <div>
    • <div id="kaisetsu">

    5. テスト方針

    • 外部依存のモック化: fe-siken.com への HTTP 通信は requestUrl スタブで代替。AnkiConnect は mock fetch でインターセプト。Vault API（ファイル操作）は in-memory モックで代替
    • fixture HTML: tests/fixtures/q61.html 等を用意し、実ページの DOM 構造（#mondai, ul.selectList span#select_*, button.selectBtn#t, h3「分類 :」div, #kaisetsu）を再現する
    • ユニットテストの独立性: 各ケースは他テストの副作用を受けない（beforeEach でモックをリセット）
    • 警告の検証: 警告ありケースは戻り値またはコールバック内に警告メッセージが含まれることをアサートする
