    DB設計（データ構造・マスタデータ定義）

    概要

    本プロジェクト（過去問道場 × Obsidian × Anki 連携プラグイン）は専用 DB サーバを持たない。データは以下の3層に永続化する。

    専用 DB を持たない理由: 本ツールは Obsidian デスクトップ版プラグインとして動作し、外部サーバを必要とせず学習者のローカル環境のみで完結する。Obsidian Vault（Markdown ファイル）と Anki（AnkiConnect 経由）がデータストアを兼ねる。

    graph TD
    A[Obsidian プラグイン] --> B[Vault Markdown]
    A --> C[data.json]
    A --> D[Anki ノート]

    B["Vault Markdown\n分野別 .md ファイル\n（問題エントリ表）"]
    C["data.json\nプラグイン設定\n（Obsidian 標準）"]
    D["Anki ノート\nノートタイプ: 過去問道場\n（AnkiConnect 経由）"]

    B -- "正規化URL で重複判定" --> D
    永続化層 役割 管理主体
    Vault Markdown 問題エントリ（出典・タイトル・分野・URL）を表形式で管理。人間が直接編集可能 Obsidian Vault（ローカルファイルシステム）
    data.json プラグイン設定（登録先フォルダ・デッキ名・AnkiConnect URL 等） Obsidian プラグイン設定ストレージ
    Anki ノート フラッシュカード（問題文・選択肢・正解・解説）。AnkiConnect 経由で CRUD Anki デスクトップアプリ

    Obsidian 問題エントリ（表スキーマ）

    ファイル配置規則

    • フォルダ: プラグイン設定「登録先フォルダ」配下（デフォルト: 過去問道場）
    • ファイル名: {大分類}-{中分類}.md（中分類単位で分割）
    • 例: テクノロジ系-データベース.md、マネジメント系-プロジェクトマネジメント.md
    • 分野が抽出できなかった問題: 未分類.md に登録する

    ファイル新規作成時の表ヘッダ

    対象ファイルが存在しない場合、以下の表ヘッダを生成してから1行目のエントリを追記する。

    | 出典 | タイトル | 分野 | 問題URL |
|------|---------|------|--------|

    列定義

    列名 型 例 制約
    出典 string H20秋期 問61 簡潔出典形式（後述）。空不可
    タイトル string データベースの障害復旧 og:title から抽出した論点名。空の場合は出典をフォールバック表示
    分野 string テクノロジ系 » データベース » トランザクション処理 大分類 » 中分類 » 小分類の3階層フル表記
    問題URL Markdown リンク [H20秋期 問61](https://www.fe-siken.com/kakomon/20_aki/q61.html) [出典](正規化URL) 形式。クリック可能なリンク

    表を最小列に保つ理由

    理解度の管理は Anki の間隔反復に委ね、Obsidian 側には保持しない。Anki 登録済みかの判定も Anki 側（AnkiConnect findNotes）で行うため、登録状態列も持たない。表は問題の所在（出典・タイトル・分野・URL）の一覧管理に専念する。

    重複判定

    正規化 URL（後述）をキーに、登録先フォルダ内の全 Markdown ファイルを横断して検索する。ヒットした場合は既存行を上書きせず「登録済み: 出典」として通知し、処理をスキップする（先勝ち）。

    プラグイン設定スキーマ（data.json）

    Obsidian のプラグイン設定ストレージ（data.json）に保存される設定。設定タブ（PluginSettingTab）から変更可能。

    設定キー 型 デフォルト値 説明
    targetFolder string 過去問道場 問題エントリを書き出す Vault フォルダ名
    ankiDeckName string 基本情報技術者::過去問道場 Anki デッキ名。:: でサブデッキ区切り
    ankiConnectUrl string http://localhost:8765 AnkiConnect エンドポイント URL
    ankiModelName string 過去問道場 Anki ノートタイプ名
    rateIntervalMs number 1000 fe-siken への連続アクセス間隔（ミリ秒）

    Anki ノートスキーマ

    ノートタイプ

    • ノートタイプ名: 過去問道場
    • 起動時に modelNames で存在確認し、なければ createModel で作成する

    フィールド定義

    フィールド名 内容 例
    問題文 問題の本文テキスト（<div id="mondai"> の innerText） 次のうち、...正しいものはどれか。
    選択肢 選択肢ア〜エの本文（改行区切り） ア 〇〇\nイ △△\nウ □□\nエ ◇◇
    正解 正解記号（ア / イ / ウ / エのいずれか） ア
    解説 解説テキスト（<div id="kaisetsu"> の innerText） 〇〇は...
    出典 簡潔出典（例: H20秋期 問61） H20秋期 問61
    分野 3階層フル分野（例: テクノロジ系 » データベース » トランザクション処理） テクノロジ系 » データベース » トランザクション処理
    URL 正規化済み問題 URL https://www.fe-siken.com/kakomon/20_aki/q61.html

    重複判定キー

    addNote 前に findNotes クエリ "URL:<正規化URL>" で既存ノートを検索する。ヒットした場合は addNote をスキップする（options.allowDuplicate = false も併用）。

    デフォルトデッキ

    基本情報技術者::過去問道場（設定変更可）。デッキが存在しない場合は createDeck で作成する。

    マスタデータ / Enum 定義

    本セクションが全 Enum の正（Single Source of Truth）。実装はここを参照する。

    元号→簡潔出典 変換表

    og:title の (平成|令和|昭和)(\d+)年(春期|秋期)問(\d+) パースで元号を以下の略記に変換する。

    元号 略記
    平成 H
    令和 R
    昭和 S

    簡潔出典フォーマット: {略記}{年}{期} 問{番号}

    例: 基本情報技術者平成20年秋期問61 → H20秋期 問61

    分野パンくず階層構造

    fe-siken の分野テキスト（テクノロジ系 » データベース » トランザクション処理）は3階層。区切り文字は »（&raquo;）。

    階層 役割 大分類の値
    第1階層（大分類） ファイル名プレフィックス テクノロジ系 / マネジメント系 / ストラテジ系
    第2階層（中分類） ファイル名サフィックス（ファイル分割単位） 例: データベース / プロジェクトマネジメント
    第3階層（小分類） 表の「分野」列に記録（参照のみ） 例: トランザクション処理

    ファイル名は {大分類}-{中分類}.md（第1・第2階層を結合）。第3階層はファイル分割に使用しない。

    URL 正規化規則

    問題 URL の重複判定・Anki URL フィールドに使用する正規化済み URL の生成規則。

    1. クエリパラメータを除去: ? 以降を削除
    2. フラグメントを除去: # 以降を削除
    3. scheme・host を小文字化: HTTPS://WWW.FE-SIKEN.COM/... → https://www.fe-siken.com/...
    4. 末尾スラッシュを統一: パスの末尾スラッシュを除去（/kakomon/20_aki/q61.html はそのまま）

    例: https://www.fe-siken.com/kakomon/20_aki/q61.html?utm_source=xxx#section → https://www.fe-siken.com/kakomon/20_aki/q61.html
