    REQ-INGEST-001 問題取り込み ロジック設計書

    1. 概要

    項目 値
    機能ID REQ-INGEST-001
    機能名 問題取り込み（URL → 抽出）
    要件定義書 REQ-INGEST-001
    上流機能 なし（本機能が取り込みの起点）
    下流機能 REQ-VAULT-001（Obsidian 登録）、REQ-ANKI-001（Anki 登録）

    HTML 抽出の一次仕様（DOM セレクタ・属性名・抽出方法の詳細）は ../api-spec.md に集約する。本書では処理フロー・バリデーションルール・データ構造・エラー処理・レート制御の設計を記述する。

    2. 処理フロー

    flowchart TD
    A([URL入力\nモーダル]) --> B[URL文字列を\n改行 or カンマで分割]
    B --> C{各URLを検証\nhost: fe-siken.com\npath: /kakomon/ または /s/ 配下か}
    C -- 非対応URL --> D[Notice表示\n対応していないURLです]
    C -- 検証OK --> E[重複URL集約\n正規化URLをキーにdedup]
    E --> F[取り込みループ\n各URL順次処理]
    F --> G[requestUrl でHTML取得]
    G --> H{HTTP 200か}
    H -- 失敗 --> I[スキップ\nNotice表示\nページを取得できませんでした URL]
    H -- 成功 --> J[DOMParser で\nHTML解析]
    J --> K[メタデータ抽出\nog:title パース]
    K --> L[問題本体抽出\n問題文 / 選択肢 / 正解 / 解説 / 画像]
    L --> M{欠落項目あり}
    M -- あり --> N[欠落項目を空にして\n警告を記録]
    M -- なし --> O[QuestionData オブジェクト生成]
    N --> O
    O --> P{次のURLあり\n かつ 間隔未経過}
    P -- 待機必要 --> Q[rateLimitMs 待機\nデフォルト 1000ms]
    Q --> F
    P -- 不要 --> F
    F -- ループ完了 --> R([QuestionData[]\n を後続へ渡す])

    3. URL 検証ルール

    条件 判定 備考
    ホストが fe-siken.com（www. 有無問わず） 必須 new URL(input).hostname で判定
    パスが /kakomon/ または /s/ で始まる 必須 標準ページ（/kakomon/）と分野別ページ（/s/bunya.php 等）
    上記いずれかを満たさない 非対応 当該URLを unsupported として処理しない

    canonical 追従（薄いラッパーページ対応）

    /s/bunya.php 等は問題本体を持たない薄いラッパーページのため、取得後に <link rel="canonical">（無ければ og:url）を読み、取得元と正規化が異なる場合は canonical の本体ページを再取得してそのHTMLから抽出する。再取得時もレート制御の間隔を空ける。

    URL 正規化（重複キー生成）

    QuestionData.normalizedUrl にはページの canonical URL を正規化した値を採用する。これにより、同一問題を /kakomon/... と /s/bunya.php?... の異なる形式で取り込んでも同一キーになり、Obsidian・Anki の両方で重複しない。

    処理 内容
    canonical を採用 <link rel="canonical"> → og:url → 取得元URL の順で決定
    scheme / host を小文字化 https://WWW.FE-SIKEN.COM/... → https://www.fe-siken.com/...
    クエリ文字列・フラグメントを除去 ?foo=1#bar を削除
    末尾スラッシュを統一 末尾 / なしに統一

    4. 出典パーサ仕様

    4.1 og:title からのパース

    og:title の content は試験年度により2形式あり、順に判定する（詳細は ../api-spec.md §3.3）。

    A 年＋期:  基本情報技術者{元号}{年}年{春期|秋期}問{番号} {タイトル}
B 年度:    基本情報技術者{元号}{年}年度問{番号} {タイトル}   ← 令和4年度〜のCBT形式（期なし）
    データ 抽出方法
    出典（正式） 形式A: (平成\|令和\|昭和)(\d+\|元)年(春期\|秋期)問(\d+) / 形式B: ...(\d+\|元)年度問(\d+)。「元」年は1年扱い
    簡潔出典 元号略記（平成→H / 令和→R / 昭和→S）＋年数（元→1）＋期（形式Bは無し）＋問＋問番号
    タイトル 最初の半角スペース以降の文字列全体

    4.2 変換例

    og:title content 簡潔出典 タイトル
    基本情報技術者平成20年秋期問61 データベースの障害復旧 H20秋期 問61 データベースの障害復旧
    基本情報技術者令和元年秋期問29 デッドロックが発生しない処理順序 R1秋期 問29 デッドロックが発生しない処理順序
    基本情報技術者令和4年度問27 エンティティの関係 R4 問27 エンティティの関係

    5. 抽出データ構造（設計提案）

    以下の型定義は設計提案であり、実装時に確定する。

    /** 選択肢の識別子 */
type ChoiceKey = 'ア' | 'イ' | 'ウ' | 'エ';

/** 取り込み結果の1問分データ */
interface QuestionData {
  /** 出典の正式表記（例: 基本情報技術者平成20年秋期問61） */
  citation: string;
  /** 出典の簡潔表記（例: H20秋期 問61） */
  shortCitation: string;
  /** タイトル・論点名（例: データベースの障害復旧） */
  title: string;
  /** 分野の3階層（例: テクノロジ系 / データベース / トランザクション処理） */
  category: {
    large: string;   // 大分類
    medium: string;  // 中分類
    small: string;   // 小分類
  };
  /** 問題文（textContent。プレーン表記・予備） */
  questionText: string;
  /** 問題文（サニタイズ済 innerHTML・画像絶対URL。改行/図表を保持。カード表示用） */
  questionHtml: string;
  /** 選択肢（ア～エ の本文テキスト。画像選択肢は空） */
  choices: Record<ChoiceKey, string>;
  /** 選択肢画像（記号ごとに別画像の場合のみ。記号→画像絶対URL） */
  choiceImages: Partial<Record<ChoiceKey, string>>;
  /** 全選択肢が1枚の共通画像で示される場合の画像絶対URL（流れ図・図表問題。空文字なら無し） */
  combinedChoiceImage: string;
  /** 正解記号（抽出不可なら空文字） */
  correctKey: ChoiceKey | '';
  /** 選択肢が画像で提供される問題か（本文 span が無く ul.selectList に img がある。例: 流れ図問題） */
  hasImageChoices: boolean;
  /** 解説文（textContent。プレーン表記・予備） */
  explanation: string;
  /** 解説（サニタイズ済 innerHTML・画像絶対URL。改行/画像を保持。カード表示用） */
  explanationHtml: string;
  /** 問題文・選択肢・解説に含まれる画像の絶対URL一覧（リモート参照） */
  imageUrls: string[];
  /** 元URL（入力値） */
  sourceUrl: string;
  /** 正規化URL（重複キー・Ankiフィールド値） */
  normalizedUrl: string;
}

    6. エラー・異常系処理

    状況 処理 ユーザー通知
    HTTP ステータスが 200 以外 当該URLをスキップして次のURLへ進む Notice「ページを取得できませんでした（URL）」
    ネットワーク障害（requestUrl 例外） 同上 同上
    URL 検証失敗（非対応サイト） 取り込みを行わず終了 Notice「対応していないURLです」
    出典・タイトル・分野のいずれかが抽出できない 該当フィールドを空文字に設定し処理継続 警告メッセージをログに記録
    選択肢数が 4 でない 取り込みは継続 警告メッセージをログに記録
    正解記号が抽出できない correctKey を空文字に設定し処理継続 警告メッセージをログに記録

    7. レート制御

    fe-siken.com への連続アクセスを1秒以上間隔で制御する（detail-design-context.md J 節）。

    項目 値
    設定キー rateLimitMs
    デフォルト値 1000（ms）
    設定場所 プラグイン設定（data.json）（detail-design-context.md H 節）
    実装方針 各 requestUrl 呼び出しの後、次の呼び出し前に await sleep(rateLimitMs) を実行。最終URLの処理後は待機不要
