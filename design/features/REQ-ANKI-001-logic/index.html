    REQ-ANKI-001 Anki 連携 ロジック設計書

    1. 概要

    項目 値
    機能ID REQ-ANKI-001
    機能名 Anki 連携（AnkiConnect 自動登録）
    要件定義書 REQ-ANKI-001
    上流機能 REQ-VAULT-001（登録対象の問題管理）、REQ-INGEST-001（問題データ抽出元）
    AnkiConnect API 仕様 ../api-spec.md（action 別 JSON 例・エンドポイント詳細はすべてこちらを参照）

    本機能は、取り込んだ問題（REQ-INGEST-001 の QuestionData）を AnkiConnect 経由で Anki に自動登録する。カードは専用ノートタイプ 過去問道場 で生成し、重複防止・一括登録を行う。登録済みかの判定は Anki 側（findNotes）に一元化し、Obsidian 表には登録状態を持たない（v1.1）。

    2. 登録シーケンス

    処理は以下の順序で実行する。AnkiConnect の action 別 JSON 詳細は ../api-spec.md を参照。

    sequenceDiagram
    participant U as ユーザー
    participant P as プラグイン
    participant A as AnkiConnect

    U->>P: コマンド「未登録の問題を Anki に登録」
    P->>A: version アクション（疎通確認）
    alt 接続不可またはタイムアウト5秒
        A-->>P: エラー
        P-->>U: Notice「Anki に接続できません。Anki と AnkiConnect を起動してください」
        note over P: 処理中断
    end
    A-->>P: バージョン番号

    P->>A: modelNames アクション
    A-->>P: ノートタイプ名一覧
    alt 「過去問道場」が存在しない
        P->>A: createModel（フィールド7個・カードテンプレート・CSS 定義）
        A-->>P: 作成完了
    else 既に存在する
        P->>A: updateModelTemplates / updateModelStyling（最新のテンプレート・CSS へ同期）
        A-->>P: 更新完了
    end

    P->>A: deckNames アクション
    A-->>P: デッキ名一覧
    alt 設定デッキ名が存在しない
        P->>A: createDeck アクション
        A-->>P: 作成完了
    end

    loop 各問題（取り込んだ QuestionData）
        P->>A: findNotes（URL:正規化URL）
        A-->>P: マッチしたノートID一覧
        alt ノートID 1件以上（重複あり）
            note over P: スキップ（重複カウント +1）
        else ノートID 0件
            P->>A: addNote アクション
            alt 登録成功
                A-->>P: ノートID
                note over P: 成功カウント +1
            else 登録失敗
                A-->>P: エラー
                note over P: 失敗カウント +1（次の問題へ継続）
            end
        end
    end

    P-->>U: Notice「登録完了 成功:N件 スキップ:N件 失敗:N件」

    3. カードフィールドマッピング

    3.1 ノートタイプ定義

    ノートタイプ名: 過去問道場（modelNames に存在しない場合は createModel で作成）

    フィールド名 対応する QuestionData 備考
    問題文 questionHtml（#mondai のサニタイズ済 HTML・画像絶対URL） 改行・図表画像を保持。空なら questionText（plain）にフォールバック
    選択肢 テキスト選択肢は本文、画像選択肢は choiceImages の <img> 記号ごとに <div class="kk-choice"> で縦並び。画像選択肢も実画像を表示（「URL参照」プレースホルダは廃止）
    正解 correctKey（正解記号）＋ 対応する選択肢本文 例: ア　ジャーナルファイル（記号と本文を全角スペースで連結）。本文が無い（画像選択肢）場合は記号のみ
    解説 explanationHtml（#kaisetsu のサニタイズ済 HTML・画像絶対URL） 改行・画像を保持。空なら explanation（plain）にフォールバック
    出典 citation（簡潔出典。例: H20秋期 問61） コンテキスト: detail-design-context.md A
    分野 category（3階層フル。例: テクノロジ系 データベース トランザクション処理） コンテキスト: detail-design-context.md A。「»」は使わず半角スペースで接続
    URL normalizedUrl（正規化済み URL） 重複判定キー兼用。コンテキスト: detail-design-context.md G

    3.2 カードテンプレート

    面 表示内容
    Front（表） ヘッダ（出典 をバッジ表示 ＋ その下に URL 小さくリンク）+ 問題文（強調）+ 選択肢（枠付き・縦並び）
    Back（裏） {{FrontSide}}（表＝出典バッジ・URL・問題・選択肢を再掲）+ 区切り線 + 正解（緑ハイライト）+ 解説（左罫線ブロック）+ 分野（小さくグレー）

    表示仕様:

    • 選択肢の縦並び: 選択肢 フィールドは改行（\n）区切りで本文を保持し、テンプレート側のラッパ要素に white-space: pre-line を適用して縦並び表示する（HTML では生の改行が無視されるため）。CSS で対応することで、既存ノートのフィールドを変更せずに表示を改善できる。
    • CSS（スタイリング）: ノートタイプの css でフォント・余白・正解の強調（緑系）・解説ブロック（左罫線）・出典/分野のグレー表示を定義する。.nightMode セレクタでダークモード時の配色も定義する。
    • 画像の表示（リモート参照）: 問題文・解説・選択肢の画像は絶対URLの <img> でカードに表示する（Anki 内に保存しない）。CSS は .card img { max-width: 100%; height: auto; background:#fff; border:1px solid #ddd; border-radius:6px; padding:4px; } とし、カード幅に合わせて元画像を等比縮小しつつ、白背景＋細枠で透過PNGがダークモード等で崩れないようにする（情報領域をきれいな四角に収める）。クロップ・高さ切り詰めはしない。画像バイトの加工（透明余白の実トリミング）はリモート参照のため行わない（必要時は storeMediaFile 方式で別途検討）。
    • ヘッダ（出典・URL）: Front 上部に 出典 をバッジ（角丸・淡色背景）で表示し、その下に問題URLを小さくリンク表示する（画像非表示時のフォールバック）。Back は FrontSide 再掲で同ヘッダを含むため、裏面下部のメタは 分野 のみとし重複を避ける。
    • ノートタイプの最新化: テンプレート・CSS の Single Source of Truth はコード（registrar.ts）に置く。既にノートタイプが存在する場合は §2 のとおり updateModelTemplates / updateModelStyling で最新定義へ同期する。

    4. 重複防止

    重複判定は addNote 実行前に findNotes アクションで行う。

    項目 内容
    判定クエリ URL:<正規化URL>
    正規化ルール クエリ・フラグメント除去 / scheme・host を小文字化 / 末尾スラッシュ統一（コンテキスト: detail-design-context.md G）
    結果 findNotes が1件以上返した場合はスキップ（登録しない）
    addNote オプション options.allowDuplicate = false（サーバー側の二重ガード）

    正規化 URL は Obsidian Vault の重複判定（REQ-VAULT-001 の表の 問題URL 列）と同一キーを使用する。

    5. 一括登録と結果集約

    5.1 登録対象の選択

    登録対象は取り込みで得た QuestionData[]（問題文・選択肢・正解・解説を保持）とする。Obsidian の表には問題本体を保持しないため、Anki カードは取り込み済みデータから生成する。各問題は登録前に findNotes（URL:<正規化URL>）で Anki 側の既存を確認し、未登録のものだけ addNote する（重複は Anki 側に一元化）。

    登録のトリガー（実装時に確定）

    MVP では取り込みフロー（REQ-INGEST-001 → REQ-VAULT-001）と同じ実行内で QuestionData[] を Anki にも登録する想定。表の URL から再取得して登録する別コマンド方式は将来拡張とする。

    5.2 結果集計と通知

    結果種別 条件 処理
    成功 addNote がノートIDを返した 成功カウント +1
    スキップ findNotes が1件以上を返した スキップカウント +1
    失敗 addNote がエラーを返した / タイムアウト 失敗カウント +1。次の問題へ継続（全体中断しない）

    全件処理後、Obsidian の Notice で以下を表示する:

    登録完了 成功:N件 スキップ:N件 失敗:N件

    6. エラー・異常系

    異常状況 検出方法 ユーザーへの通知 処理継続
    Anki 未起動・接続不可 version アクションが失敗 / タイムアウト5秒 「Anki に接続できません。Anki と AnkiConnect を起動してください」（Notice） 中断
    CORS 拒否 HTTP 403 / ネットワークエラー 「AnkiConnect の設定で webCorsOriginList に app://obsidian.md を追加してください」（Notice） 中断
    タイムアウト（個別リクエスト） 5秒超過 当該1件を失敗として集計 残り件数を継続
    addNote 失敗（その他） error フィールドが非 null 当該1件を失敗として集計 残り件数を継続

    タイムアウト値 5秒 の根拠: api-spec.md AnkiConnect 契約。

    7. 登録状態の管理（Obsidian 表への反映なし）

    登録済みかの状態は Anki 側に一元化する。Obsidian の表には登録状態列を持たない（v1.1）。

    • 重複判定は登録の都度 findNotes（URL:<正規化URL>）で Anki に問い合わせる
    • 同じ問題を再度取り込んでも、Anki 側に既存ノートがあれば addNote をスキップするため二重登録されない
    • Obsidian 表の 問題URL 列の正規化URLと Anki ノートの URL フィールドが同一キーであり、両者の突合は不要（Anki 側の検索で完結する）
