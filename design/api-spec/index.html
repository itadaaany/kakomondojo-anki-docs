    外部連携仕様書

    1. 概要

    本プロジェクトは自前の REST API サーバを持たない。外部との通信は次の2系統に限定される。

    1. fe-siken.com スクレイピング（読み取り専用 GET）: 過去問道場のページ HTML を取得し、問題データを抽出する
    2. AnkiConnect（localhost HTTP/JSON）: ローカルで起動中の Anki に問題カードを登録する

    いずれも Obsidian デスクトップ版（Electron）プラグイン内から直接呼び出す。中間サーバは存在しない。

    2. 外部連携一覧

    サービス名 方向 プロトコル 用途 関連 Spec
    fe-siken.com 受信（GET） HTTPS 問題ページ HTML の取得 REQ-INGEST-001
    AnkiConnect 送受信（POST） HTTP/JSON (localhost) Anki へのデッキ・ノート操作 REQ-ANKI-001

    3. fe-siken.com スクレイピング仕様

    3.1 接続概要

    項目 値
    接続先 https://www.fe-siken.com/kakomon/{年度}_{期}/q{番号}.html（標準）
    対応URL ホストが fe-siken.com（www任意）かつパスが /kakomon/ または /s/ 配下（/s/bunya.php 分野別等）
    メソッド GET
    認証 なし
    取得 API Obsidian requestUrl（Electron CORS 回避）
    タイムアウト 明示指定なし（Obsidian デフォルト）
    レート制限 リクエスト間隔 1秒以上（連続取得時。canonical 追従の再取得も間隔を空ける）
    障害時の動作 HTTP 200 以外 / ネットワーク失敗 → 当該 URL をスキップして次へ継続

    canonical 追従と重複キー

    /s/bunya.php 等は問題本体を持たない薄いラッパーページのため、取得後に <link rel="canonical">（無ければ og:url）を読み、取得元と異なる場合は canonical の本体ページを再取得して抽出する。

    QuestionData.normalizedUrl（Obsidian 重複判定・Anki URL フィールドの重複キー）には、ページの canonical URL を正規化した値を採用する。これにより、同一問題を /kakomon/... と /s/bunya.php?... の異なる形式で取り込んでも、同一キーとなり Obsidian・Anki の両方で重複登録されない。標準ページの canonical は自己 URL（クリーンな /kakomon/ 形式）を指す。

    3.2 HTML 抽出契約

    実ページ（https://www.fe-siken.com/kakomon/20_aki/q61.html）の精査で確定した DOM 抽出仕様。

    データ 抽出元（DOM） 抽出方法
    og:title（原文） <meta property="og:title" content="..."> content 属性値。形式: 基本情報技術者{元号}{年}年{期}問{番号} {タイトル}
    タイトル（論点名） og:title の content 最初の半角スペース以降の文字列。例: データベースの障害復旧
    出典（正式） og:title の content 前半 正規表現でパース（後述）。例: 平成20年秋期 問61
    出典（簡潔） 上記パース結果 元号略記変換（後述）。例: H20秋期 問61
    分野 <h3>分類 :</h3> 直後の <div> のテキスト »（&raquo;）区切りの3階層テキスト。末尾は <a> 内テキスト
    問題文（テキスト） <div id="mondai"> textContent（プレーン表記。予備）
    問題文（HTML） <div id="mondai"> innerHTML をサニタイズし画像を絶対URL化（改行・図表画像を保持）。カード表示に使用
    選択肢記号 ul.selectList button.selectBtn のテキスト ボタンの記号（ア/イ/ウ/エ）を選択肢キーとする。選択肢の有無・件数はボタン基準で判定する
    選択肢本文（テキスト型） 記号に対応する <span id="select_a\|select_i\|select_u\|select_e"> textContent。span が無い記号は本文空（画像型）
    選択肢画像（画像型） 各記号ボタンの closest('li') 内の <img src> 絶対URL化して記号ごとに保持。カードで <img> 表示する
    正解 ul.selectList button.selectBtn#t のテキスト記号 id="t" を持つ button.selectBtn が正解選択肢。フォールバック: <h3>正解 :</h3> 直後のテキスト
    解説（テキスト） <div id="kaisetsu"> textContent（プレーン表記。予備）
    解説（HTML） <div id="kaisetsu"> innerHTML をサニタイズし画像を絶対URL化（改行・画像を保持）。カード表示に使用。選択肢別解説 <li class="lia\|lii\|liu\|lie">（a/i/u/e=ア/イ/ウ/エ）は class 除去前に各項目頭へ「記号：」を付与して対応を保持する
    画像 上記各領域内の <img src> 相対パスを絶対 URL 化（後述）。リモート参照方式（ローカル保存しない）。問題文/解説は HTML 内に内包、選択肢画像は記号ごとに保持

    HTML サニタイズ方針: <script>/<style>/<iframe> 等を除去し、属性は src/href/alt/colspan/rowspan のみ残す（width/height/class/style/on* は除去しサイズは CSS 制御）。img/a の相対URLは絶対化する。取得元は信頼済み fe-siken のみのため最小サニタイズとする。

    選択肢の2レイアウト（実ページ精査・REQ-INGEST-001 実装で確定）

    fe-siken には選択肢の表現が2種類ある。抽出は ul.selectList button.selectBtn のボタン記号を基準にすることで両対応する。

    1. テキスト選択肢（例 q61）: 各 <li> に <button>記号</button><span id="select_X">本文</span>。本文が span から取れる
    2. 画像選択肢（例 q1/q29: 流れ図・図表問題）: 本文 span が無く <img> で示す。さらに2パターンに分かれる:
      • 共通画像（1枚）: 1つの <li> に1枚の <img> ＋ 記号ボタン（ア〜エ）が並ぶ。画像自体に4択が描かれている。→ QuestionData.combinedChoiceImage（1枚）に集約し、カードでは1枚だけ表示する（記号別に4回表示しない）
      • 記号別画像: 記号ごとに別々の <img> がある。→ QuestionData.choiceImages（記号→画像URL）に保持し、記号ごとに表示する

    判定: 各記号ボタンの closest('li') 内 <img> を集め、全記号が同一の img 要素を共有していれば共通画像（combinedChoiceImage）、要素が記号ごとに異なれば記号別画像（choiceImages）。本文 span が1つも無く画像があれば hasImageChoices = true。

    3.3 出典パーサ

    og:title は試験年度により2形式あり、順に判定する。

    形式A: 年＋期（春期/秋期）

    基本情報技術者(平成|令和|昭和)(\d+|元)年(春期|秋期)問(\d+)
    • キャプチャ: (1)元号 / (2)年（数字 or「元」） / (3)期 / (4)問番号
    • 正式出典: {元号}{年}年{期} 問{番号}（例: 令和元年秋期 問29）
    • 簡潔出典: {略記}{年数}{期} 問{番号}（例: R1秋期 問29）
    • 「元」年は1年として扱う（令和元年 → R1）

    形式B: 年度（CBT通年・期なし。令和4年度〜）

    基本情報技術者(平成|令和|昭和)(\d+|元)年度問(\d+)
    • 正式出典: {元号}{年}年度 問{番号}（例: 令和4年度 問27）
    • 簡潔出典: {略記}{年数} 問{番号}（例: R4 問27）

    簡潔出典への変換規則（元号略記）

    元号 略記
    平成 H
    令和 R
    昭和 S

    例: 基本情報技術者平成20年秋期問61 → H20秋期 問61 / 基本情報技術者令和元年秋期問29 → R1秋期 問29 / 基本情報技術者令和4年度問27 → R4 問27

    いずれの形式にも一致しない場合は出典・タイトルを空にして警告を残す。

    3.4 分野文字列のパース

    抽出テキスト例: テクノロジ系 » データベース » トランザクション処理

    • 区切り文字: »（U+00BB、HTML エンティティ &raquo;）
    • 分割後: ["テクノロジ系", "データベース", "トランザクション処理"]
    • 対応: [0] = 大分類 / [1] = 中分類 / [2] = 小分類
    • 3階層に満たない場合は警告を残して取り込みを継続する

    3.5 画像の絶対 URL 化

    • 基底 URL: https://www.fe-siken.com
    • 対象: mondai, kaisetsu 領域内の <img src> で相対パスのもの
    • 変換: src が http で始まらない場合、https://www.fe-siken.com を前置して絶対 URL にする
    • MVP では絶対 URL 参照のまま保持する（Vault へのローカル保存は将来拡張）

    3.6 エラーハンドリング

    状況 処理
    HTTP ステータス非 200 当該 URL をスキップ。エラー: ページを取得できませんでした（{URL}）
    ネットワーク失敗 同上
    項目が抽出できない 該当項目を空にして取り込み継続。警告メッセージを残す

    3.7 利用規約・倫理的注記

    • スクレイピングは個人学習用途に限定する
    • robots.txt および fe-siken.com 利用規約を尊重する
    • 取得データの再配布はしない
    • 認証情報・個人情報は保存しない

    4. AnkiConnect 仕様

    4.1 接続概要

    項目 値
    エンドポイント http://localhost:8765（設定で変更可）
    メソッド POST
    Content-Type application/json
    プロトコルバージョン 6
    タイムアウト 5秒
    障害時の動作 1件失敗で全体中断せず、残りを継続
    接続不可メッセージ Anki に接続できません。Anki と AnkiConnect を起動してください

    CORS 設定

    AnkiConnect の設定ファイル内 webCorsOriginList に以下を追加する必要がある:

    "webCorsOriginList": ["app://obsidian.md"]

    4.2 共通リクエスト形式

    {
  "action": "<action名>",
  "version": 6,
  "params": { }
}

    4.3 使用 action 一覧

    version（疎通確認）

    リクエスト: 

    {
  "action": "version",
  "version": 6
}

    レスポンス: 

    {
  "result": 6,
  "error": null
}

    deckNames（デッキ一覧取得）

    リクエスト: 

    {
  "action": "deckNames",
  "version": 6
}

    レスポンス: 

    {
  "result": ["Default", "基本情報技術者::過去問道場"],
  "error": null
}

    createDeck（デッキ作成）

    リクエスト: 

    {
  "action": "createDeck",
  "version": 6,
  "params": {
    "deck": "基本情報技術者::過去問道場"
  }
}

    レスポンス: 

    {
  "result": 1712345678901,
  "error": null
}

    modelNames（ノートタイプ一覧取得）

    リクエスト: 

    {
  "action": "modelNames",
  "version": 6
}

    レスポンス: 

    {
  "result": ["Basic", "過去問道場"],
  "error": null
}

    createModel（ノートタイプ作成）

    modelNames に 過去問道場 が存在しない場合に実行する。

    リクエスト: 

    {
  "action": "createModel",
  "version": 6,
  "params": {
    "modelName": "過去問道場",
    "inOrderFields": ["問題文", "選択肢", "正解", "解説", "出典", "分野", "URL"],
    "css": "<カード CSS。SSOT は registrar.ts の CARD_CSS>",
    "cardTemplates": [
      {
        "Name": "問題-解答",
        "Front": "<div class=\"kk-head\"><span class=\"kk-citation\">{{出典}}</span><div class=\"kk-source-top\"><a href=\"{{URL}}\">{{URL}}</a></div></div><div class=\"kk-question\">{{問題文}}</div><div class=\"kk-choices\">{{選択肢}}</div>",
        "Back": "{{FrontSide}}<hr class=\"kk-sep\"><div class=\"kk-answer\">正解：{{正解}}</div><div class=\"kk-explanation\">{{解説}}</div><div class=\"kk-meta\">{{分野}}</div>"
      }
    ]
  }
}

    選択肢の縦並びは css の .kk-choices { white-space: pre-line; } で実現する（選択肢 フィールドは改行区切りの生テキストを保持）。CSS には正解の強調・解説ブロック・.nightMode のダーク配色を含める。テンプレート・CSS の Single Source of Truth はコード（registrar.ts）に置く。

    updateModelTemplates / updateModelStyling（既存ノートタイプの最新化）

    modelNames に 過去問道場 が既に存在する場合、createModel の代わりに以下を実行してテンプレート・CSS を最新定義へ同期する。

    リクエスト（updateModelTemplates）: 

    {
  "action": "updateModelTemplates",
  "version": 6,
  "params": {
    "model": {
      "name": "過去問道場",
      "templates": {
        "問題-解答": {
          "Front": "<div class=\"kk-question\">{{問題文}}</div><div class=\"kk-choices\">{{選択肢}}</div>",
          "Back": "{{FrontSide}}<hr class=\"kk-sep\"><div class=\"kk-answer\">正解：{{正解}}</div>…"
        }
      }
    }
  }
}

    リクエスト（updateModelStyling）: 

    {
  "action": "updateModelStyling",
  "version": 6,
  "params": {
    "model": {
      "name": "過去問道場",
      "css": "<カード CSS。SSOT は registrar.ts の CARD_CSS>"
    }
  }
}

    いずれも成功時は {"result": null, "error": null} を返す。

    レスポンス: 

    {
  "result": { "id": 1712345678902, "name": "過去問道場" },
  "error": null
}

    findNotes（重複チェック）

    addNote 前に実行し、同一 URL のノートが既に存在するかを確認する。

    リクエスト: 

    {
  "action": "findNotes",
  "version": 6,
  "params": {
    "query": "URL:https://www.fe-siken.com/kakomon/20_aki/q61.html"
  }
}

    レスポンス（既存あり）: 

    {
  "result": [1712345678903],
  "error": null
}

    レスポンス（既存なし）: 

    {
  "result": [],
  "error": null
}

    addNote（ノート追加）

    findNotes の結果が空（重複なし）の場合のみ実行する。

    リクエスト: 

    {
  "action": "addNote",
  "version": 6,
  "params": {
    "note": {
      "deckName": "基本情報技術者::過去問道場",
      "modelName": "過去問道場",
      "fields": {
        "問題文": "データベースの更新記録として保存するファイルはどれか。",
        "選択肢": "ア: ジャーナルファイル\nイ: インデックスファイル\nウ: バックアップファイル\nエ: テンポラリファイル",
        "正解": "ア　ジャーナルファイル",
        "解説": "ジャーナルファイルはデータベースへの更新記録（ログ）を保存するファイルである。...",
        "出典": "H20秋期 問61",
        "分野": "テクノロジ系 データベース トランザクション処理",
        "URL": "https://www.fe-siken.com/kakomon/20_aki/q61.html"
      },
      "options": {
        "allowDuplicate": false
      },
      "tags": []
    }
  }
}

    レスポンス（成功）: 

    {
  "result": 1712345678904,
  "error": null
}

    レスポンス（重複によるエラー）: 

    {
  "result": null,
  "error": "cannot create note because it is a duplicate"
}

    notesInfo（登録済みノート情報取得）

    登録済みノートのフィールド検証に使用する補助 action（MVP の登録フローでは未使用。findNotes の結果で重複判定が完結するため）。

    {

  "version": 6,
  "params": {
    "notes": [1712345678904]
  }
}

    レスポンス: 

    {
  "result": [
    {
      "noteId": 1712345678904,
      "modelName": "過去問道場",
      "fields": {
        "URL": { "value": "https://www.fe-siken.com/kakomon/20_aki/q61.html", "order": 6 }
      }
    }
  ],
  "error": null
}

    4.4 重複判定フロー

    1. URL を正規化する（クエリ・フラグメント除去、scheme/host 小文字化、末尾スラッシュ統一）
2. findNotes クエリ: "URL:<正規化URL>"
3. result が空でない（ノート ID が返る）→ 登録スキップ（スキップカウント +1）
4. result が空 → addNote を実行
5. addNote 成功（ノート ID が返る）→ 成功カウント +1
6. addNote 失敗（error != null）→ 当該1件を失敗扱い。残りを継続

    登録状態は Anki 側に一元化し、Obsidian 表には登録列を持たない（v1.1。REQ-ANKI-001 §7 参照）。

    4.5 URL 正規化ルール（重複キー）

    • クエリパラメータ（?...）を除去する
    • フラグメント（#...）を除去する
    • scheme（https）および host（www.fe-siken.com）を小文字化する
    • 末尾スラッシュを統一する（パスの末尾に付けない）

    例: https://www.fe-siken.com/kakomon/20_aki/q61.html?ref=foo#ans → https://www.fe-siken.com/kakomon/20_aki/q61.html

    この正規化 URL を Obsidian 重複判定・Anki URL フィールドの両方で重複キーとして使用する。

    4.6 エラーハンドリング

    状況 処理
    接続タイムアウト（5秒超過） 当該1件を失敗として記録し、残りを継続
    error フィールドが null 以外 当該1件を失敗として記録し、残りを継続
    Anki 未起動 / 接続拒否 Anki に接続できません。Anki と AnkiConnect を起動してください を Notice 表示
    CORS 拒否 AnkiConnect の webCorsOriginList に app://obsidian.md を追加する手順を案内
