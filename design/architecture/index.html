    アーキテクチャ概要

    1. システム概要

    過去問道場（fe-siken.com）の問題ページから出典・問題文・選択肢・正解・解説を取得し、Obsidian Vault の分野別 Markdown ファイルに登録するとともに、AnkiConnect 経由で Anki カードを自動生成する Obsidian デスクトップ版プラグイン。サーバーサイドは持たず、全処理はローカルの Electron プロセス内で完結する。

    3. モジュール構成

    実装済みの主なモジュール（コードリポ kakomondojo-anki/src/）。

    モジュール ファイル 責務
    エントリポイント main.ts Plugin クラス、コマンド登録、設定タブ、URL入力/確認モーダル、ObsidianVaultGateway、取り込み/Inbox のオーケストレーション
    共通型 types.ts QuestionData・設定型・デフォルト値
    ユーティリティ util/url.ts URL 正規化・対応URL判定
    ユーティリティ util/html.ts HTML サニタイズ・URL 絶対化・エスケープ
    取り込み層 ingest/fetcher.ts requestUrl による HTML 取得（ブラウザUA・リトライ・レート制御）
    取り込み層 ingest/sourceParser.ts og:title から出典・簡潔出典・タイトルをパース（年＋期 / 年度 両形式）
    取り込み層 ingest/htmlExtractor.ts DOMParser で問題文・選択肢・正解・解説・分野・画像・canonical を抽出
    取り込み層 ingest/inputs.ts 入力URLの検証・入力段の重複除外
    取り込み層 ingest/index.ts 取り込みオーケストレーション（検証→取得→canonical追従→抽出→バッチ重複除外）
    Vault 層 vault/categoryFile.ts 分野（中分類）からファイル名を決定。未分類は 未分類.md
    Vault 層 vault/table.ts 表ヘッダ生成・行生成・追記・URL抽出
    Vault 層 vault/registrar.ts VaultGateway 抽象・横断重複判定・登録（Inbox ファイルは走査除外）
    Anki 層 anki/client.ts AnkiConnect HTTP クライアント（FetchAnkiInvoker）
    Anki 層 anki/cardBuilder.ts ノートフィールド・選択肢/解説の組み立て
    Anki 層 anki/registrar.ts ノートタイプ/デッキ確保・findNotes 重複判定・一括登録・カードCSS/テンプレートの SSOT
    Anki 層 anki/types.ts AnkiInvoker・AnkiConnectionError・結果型
    Inbox 層 inbox/inbox.ts Inbox 本文からの URL 抽出・登録済みURLの行削除

    設定タブ・モーダル・Vault アダプタは main.ts 内に実装。テストは各純ロジックを単体で検証する。

    4. データフロー

    4.1 取り込みフロー（URL 入力 → Obsidian 登録）

    sequenceDiagram
    participant U as 利用者
    participant M as URLモーダル
    participant F as fetcher
    participant P as parser
    participant V as Vault 層

    U->>M: URLを入力して確定
    M->>F: fetch(url)
    F->>+FeSiken: requestUrl GET
    FeSiken-->>-F: HTML レスポンス
    F->>P: parseHTML(html)
    P-->>F: 構造化データ（問題文・選択肢・正解・解説・分野・出典）
    F->>V: save(question)
    V->>V: URL正規化 → 重複チェック
    V->>V: ファイルパス決定（中分類）
    V->>Vault: 表行追加（またはスキップ）
    V-->>M: 登録結果
    M-->>U: Notice通知

    4.2 Anki 登録フロー

    Anki 登録は独立コマンドではなく、取り込みフロー（および Inbox 処理）の後半として、Obsidian 登録に続けて実行される。対象は取り込んだ QuestionData 群で、重複は Anki 側 findNotes で判定する（Obsidian 表を走査しない）。

    sequenceDiagram
    participant M as main(取り込み/Inbox)
    participant R as anki/registrar
    participant A as AnkiConnect

    M->>R: registerToAnki(取り込んだ問題群)
    R->>+A: version（疎通確認。失敗時は中断しNotice案内）
    A-->>-R: バージョン番号
    R->>A: modelNames / createModel または updateModelTemplates・updateModelStyling
    R->>A: deckNames / createDeck（未存在時）
    loop 取り込んだ問題ごと
        R->>+A: findNotes（URL で重複チェック）
        A-->>-R: ノートID一覧
        alt 未登録
            R->>A: addNote
        end
    end
    R-->>M: 結果（成功・スキップ・失敗の件数）

    5. UI surface

    surface 種別 説明
    過去問道場: URLから問題を取り込む コマンド URL 入力モーダルを開く。単一または複数 URL を受け付け、取り込み→Obsidian登録→Anki登録を実行
    過去問道場: Inboxを処理する コマンド Inbox.md の URL を抽出して確認ダイアログを表示。承認後に一括取り込み→登録し、Anki 登録済みURLを Inbox から削除
    URL 入力モーダル Modal テキストエリア形式で URL を入力。複数行入力に対応
    Inbox 確認ダイアログ Modal Inbox 内の URL 件数と一覧を表示し、承認/キャンセルを選ぶ
    Notice 通知 取り込み・登録・Anki 結果・Inbox 削除件数を表示
    設定タブ PluginSettingTab 登録先フォルダ / Anki デッキ名 / AnkiConnect URL / ノートタイプ名 / レート制御間隔(ms) / Inbox ファイル名 を設定

    6. 技術選定と理由

    技術 採用理由
    TypeScript + esbuild Obsidian プラグインの標準構成。型安全性とビルド速度を両立
    Obsidian requestUrl API Electron 環境では fetch を直接使うと CORS エラーが発生する。requestUrl は Obsidian が提供する CORS 回避済みの HTTP クライアントであり、デスクトッププラグインの標準手段
    DOMParser（Electron 環境） Electron はブラウザ互換の DOM API を持つため、外部ライブラリ不要で HTML を解析できる
    Obsidian Vault API（Markdown 永続化） 専用 DB を持たず、Vault の Markdown ファイルを永続化層として使うことで、Obsidian のエコシステム（検索・リンク・テーマ等）をそのまま活用できる
    AnkiConnect（HTTP/JSON） Anki の公式アドオンが提供する REST ライクな API。localhost:8765 への POST で Anki を外部から操作できる唯一の標準インタフェース

    fetch を使わない理由

    Obsidian プラグインは Electron レンダラープロセス上で動作する。ブラウザの同一オリジンポリシーにより、fetch で https://www.fe-siken.com を直接取得すると CORS エラーが発生する。requestUrl はこの制約を回避するための Obsidian 公式 API であり、プラグインから外部サイトにアクセスする場合は必ず requestUrl を使用する。

    7. 非機能要点

    詳細は REQ-OVERVIEW-001 を参照。セキュリティ設計詳細は security-design.md、セットアップ手順は setup-guide.md に記載。

    観点 要点
    パフォーマンス 1問の解析（取得後パース〜構造化）1秒以内、取り込み全体3秒以内（ネットワーク除く）
    レート制御 fe-siken.com への連続アクセスは1リクエストあたり1秒以上の間隔（ingest/fetcher.ts が管理）
    セキュリティ 外部送信は fe-siken.com への GET と localhost の AnkiConnect 通信のみ。認証情報・個人情報を保存しない
    可搬性 Obsidian デスクトップ版（Electron）を対象とする。モバイル版は対象外
