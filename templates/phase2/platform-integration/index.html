    プッシュ通知 Backend → Mobile 単方向 -
    認証共有 Web ↔ Mobile 双方向 -

    2. ディープリンク設計

    2.1 URLマッピング

    Web URL パターン アプリ画面 パラメータ フォールバック
    /items/:id 商品詳細画面 item_id Web版を表示
    /invite/:code 招待受理画面 invite_code ストアに誘導

    2.2 設定ファイル

    プラットフォーム 設定ファイル 設定内容
    iOS apple-app-site-association Universal Links ドメイン定義
    Android assetlinks.json App Links 検証用
    Web（バックエンド） .well-known/ 配下 上記ファイルの配信

    3. プッシュ通知設計

    3.1 通知フロー

    sequenceDiagram
    participant App as モバイルアプリ
    participant API as バックエンド
    participant FCM as FCM / APNs

    App->>API: デバイストークン登録
    API->>FCM: 通知送信リクエスト
    FCM->>App: プッシュ通知配信
    App->>App: 通知タップ → 画面遷移

    5.1 同期方針

    項目 方針
    同期方式 -
    コンフリクト解決 Last Write Wins / サーバー優先 / ユーザー選択
    同期対象データ -
    オフライン時の操作制限 -

    5.2 同期フロー

    sequenceDiagram
    participant App as モバイルアプリ
    participant Local as ローカルDB
    participant API as バックエンド

    App->>Local: オフライン操作を保存
    Note over App,Local: ネットワーク復帰
    App->>API: 未同期データを送信
    API->>App: サーバー側の最新データを返却
    App->>Local: ローカルDBを更新
