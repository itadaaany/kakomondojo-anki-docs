    REQ-INBOX-001 Inbox キュー処理

    概要

    過去問道場/Inbox.md に貼り付けた問題URLを、手動コマンド＋確認ダイアログで一括処理し、取り込み（REQ-INGEST-001）→ Obsidian 登録（REQ-VAULT-001）→ Anki 登録（REQ-ANKI-001）まで実行する。Anki に登録できた URL は Inbox から自動削除する（後追いの手作業を不要にする）。

    URL をその都度処理せず Inbox に溜めておき、まとめて取り込める。処理は PC（デスクトップ Obsidian＋Anki）でのみ行う。

    関連 Spec

    • REQ-INGEST-001: URL の取り込み・抽出
    • REQ-VAULT-001: Obsidian 分野別ファイルへの登録
    • REQ-ANKI-001: AnkiConnect への登録
    • REQ-OVERVIEW-001: サービス全体の前提

    アクター

    • 学習者: iPhone で Inbox に URL を投入し、PC で処理コマンドを実行・承認する

    機能要件

    REQ-INBOX-001-1 Inbox ファイル

    問題URLを溜める単一の Markdown ファイル。

    受入条件:

    • [ ] Inbox ファイルは登録先フォルダ配下の Inbox.md（設定で変更可、デフォルト Inbox.md）
    • [ ] Inbox ファイルは重複判定・分野別登録の対象外（分野別ファイルとして扱わない）
    • [ ] Inbox ファイル内の fe-siken URL を形式に依らず抽出する（プレーン / Markdown リンク / 箇条書き）

    REQ-INBOX-001-2 手動トリガーと承認

    URL 投入時ではなく、明示コマンドと人の承認で処理を起動する。

    受入条件:

    • [ ] コマンド「過去問道場: Inboxを処理する」を提供する
    • [ ] コマンド実行時、Inbox 内の URL 件数と一覧を確認ダイアログに表示し、ユーザーが承認した場合のみ処理を実行する
    • [ ] Inbox が存在しない、または URL が0件の場合はその旨を通知して処理しない

    REQ-INBOX-001-3 処理と Inbox からの削除

    承認後に取り込み〜登録を実行し、Anki 登録済みの URL を Inbox から削除する。

    受入条件:

    • [ ] 抽出した URL を REQ-INGEST-001 → REQ-VAULT-001 → REQ-ANKI-001 のパイプラインで処理する
    • [ ] Anki に登録できた URL（新規成功＋既存スキップ）を Inbox から削除する
    • [ ] Anki 登録に失敗した URL（接続不可・個別失敗）、非対応URL、取得失敗URL は Inbox に残す（再実行可能にする）
    • [ ] 削除後、Inbox の URL が0件になった場合もファイル自体は残す（ヘッダ等のユーザー記述を消さない）
    • [ ] 処理結果（取り込み / 登録 / Anki成功・スキップ・失敗 / Inbox削除件数）を通知する

    非機能要件

    • 可搬性: 処理は PC（デスクトップ Obsidian）のみ（isDesktopOnly 維持）
    • その他の共通要件は REQ-OVERVIEW-001 に従う
